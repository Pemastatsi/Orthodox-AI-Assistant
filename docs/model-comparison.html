Orthodox AI Assistant — Project Fit Analysis

Which model fits the Orthodox AI Assistant project?

The project is a closed-corpus theological Q&A system (Phase 1) with strict citation verification, safety gates, multi-tenant isolation, and route-certification requirements. Reliability and correctness are non-negotiable; cost is secondary at this stage.

Serving Model (A1/A2/A5)

Claude Opus 4.7

The only correct choice for Phase 1 LLM serving. Anthropic is the only certified provider in the architecture — the startup refuses to load an uncertified route. All 20 canonical safety cases must pass before any model enters production.

  • Already the designated certified primary in AGENTS.md and code-gen-guide.md
  • Best instruction-following precision for closed-corpus enforcement (no hallucination tolerance)
  • Structured JSON output and prompt caching natively supported
  • 87.6% SWE-Bench Verified — highest reliability on hard tasks
  • Phase 1 is low-volume (≥50 queries to exit) — cost advantage of cheaper models is irrelevant now
  • A5 (evidence composition) demands the highest-scrutiny route: Opus 4.7 is the safe choice

Development Tooling (IDE)

Cursor + Composer 2.5

Excellent choice for writing the actual project code. Composer 2.5 is not a general API model — it only runs inside Cursor — but for scaffolding FastAPI routes, Next.js components, Alembic migrations, and Qdrant adapters, it provides near-Opus quality at ~10x lower cost.

  • Cannot be integrated as an LLM provider in the serving architecture (Cursor IDE only)
  • Strong at multi-file edits and long-running agent tasks — suits T-001 to T-007 scaffolding
  • CursorBench 63.2% beats Opus 4.7 (61.6%) on IDE-specific coding tasks
  • $0.07–$0.44 per coding task vs $4.82 for Opus — use it to write code, not serve theology

Future Consideration (Phase 2+)

Minimax M2.7

Not suitable for Phase 1 — it is not a certified provider, and the project explicitly prohibits automatic cross-provider fallback. However, its open-source nature and low cost make it worth evaluating for Phase 2 high-volume agentic workloads.

  • No Anthropic provider interface — cannot slot into Phase 1 certified routes
  • Self-evolving agents are interesting but unpredictable; the project demands deterministic safety
  • Phase 2 could certify an M2.7 route as a cost-efficient fallback for A1/A2 (query analysis)
  • Open-source weights allow local deployment — appealing for privacy-sensitive theological content
  • Requires full 20-case safety suite certification before any production use
⚡

Recommended Combination for This Project

Serving layer (production): Claude Opus 4.7 — already the certified primary, non-negotiable for Phase 1 given the closed-corpus, citation-verification, and safety-gate requirements. Phase 1 is too low-volume for cost to be a deciding factor.

Development tooling: Cursor IDE with Composer 2.5 — use it to write and scaffold the FastAPI backend, Next.js frontend, Qdrant adapters, and Alembic migrations. Near-Opus coding quality at a fraction of the cost per task.

Minimax M2.7: Table it for Phase 2 route certification as a cost-efficient fallback for non-composition steps (A1/A2 query analysis). Self-hosting the open-source weights is worth exploring for privacy compliance given the ecclesiastical nature of the content.
