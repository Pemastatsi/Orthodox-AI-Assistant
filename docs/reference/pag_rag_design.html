Is this traditional RAG?

No. It is closed-corpus, multi-agent RAG with deferred graph augmentation — internally branded PAG-RAG (Private Agentic Graph-RAG). Click any node to learn more.

Traditional RAG

  • Retrieve → stuff prompt → generate
  • Open knowledge OK as fallback
  • One LLM call
  • Citations optional / soft
  • Single tenant assumption

PAG-RAG (this app)

  • 6-agent pipeline A1 → A6
  • Closed-corpus only · fail closed
  • Deterministic A4 admission gate
  • A6 verifies every citation
  • Tenant-scoped from day 1
  • Graph metadata layered on later

Overview

This pipeline answers a user query strictly from tenant_id-approved chunks. The architecture is vector-first in MVP (Qdrant), with a planned graph-aware retrieval layer in Phase 3 that draws only from reviewed lineage edges in PostgreSQL.

The five locked rules: closed corpus, tenant isolation, deterministic A4 admission, A5 composes only from the EvidencePacket, and A6 verifies citations before any text reaches the user.

The 6-agent pipeline

  • A1 classifies intent and sensitivity, transparently reframes pastoral/medical advice into teaching form.
  • A2 plans retrieval (filters, boosts, answer mode, k) — never rewrites the user's intent.
  • A3 runs vector retrieval against approved tenant chunks.
  • A4 deterministically admits chunks: tenant + approval + role + thresholds + citation-health → EvidencePacket.
  • A5 composes the answer using only admitted evidence.
  • A6 verifies citation existence, ≥70% quote overlap, schema completeness, and safety handling.

Phased rollout

  • Phase 1 (now): vector RAG, deterministic admission, citation verification.
  • Phase 2: candidate graph entities and edges captured at ingest, admin-only.
  • Phase 3: graph-aware retrieval for consensus, historical_development, scholarly_dispute — uses approved edges only.
  • Phase 4+: passage alignment, translation variants, manuscript witness graphs.
