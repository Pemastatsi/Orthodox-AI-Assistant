# Schema → Code Map

Status: Manual placeholder, regenerated by REC-009 codegen once T-008's amendment to T-001 lands.
Date: 2026-05-22

This document is the eventual auto-generated mapping between `docs/schemas/*.json`, `docs/api/openapi.yaml`, and the generated Pydantic / TypeScript / Zod artifacts that the application consumes. Until the codegen toolchain in REC-009 lands, the table below is a manual approximation. The codegen target is `make codegen` per T-008 §Amendments to T-001 (REC-009).

## Provenance contract

When generation lands:

- **Source of truth:** the files under `docs/schemas/` and `docs/api/openapi.yaml`. These are hand-edited; everything else is generated.
- **Generators** (`make codegen`):
  - `datamodel-code-generator` → `backend/app/domain/models/_generated/` (Pydantic v2).
  - `openapi-typescript` → `web/lib/api-client.generated.ts` (frontend API client types).
  - `json-schema-to-typescript` (or `zod-from-json-schema`) → `web/lib/schemas/_generated/` (frontend runtime validators).
- **Drift check:** `make codegen-check` regenerates into a temp dir and `diff`s against committed artifacts. Mismatch fails CI.
- **Manual edits forbidden:** the `_generated/` directories are flagged `linguist-generated=true` in `.gitattributes`; reviewers should reject any PR that hand-edits a generated file.

## Notes

- The table is updated by the codegen step on every `make codegen` run; reviewers cross-check against this file when reviewing schema PRs.
- Schemas whose definitions reference other schemas (`$ref`) generate one file per top-level schema; the codegen toolchain resolves refs transparently.
- The OpenAPI file at `docs/api/openapi.yaml` references the JSON schemas; `openapi-typescript` consumes the bundled OpenAPI to produce the API client.
- The Phase-1 OpenAPI bundle step is documented in `code-gen-guide.md` §9 (Toolchain).
