2. Project Goal

The product goal, restated from primary sources:

“Build a closed-corpus Orthodox theological assistant for tenant-approved libraries. The assistant answers only from approved tenant-visible evidence and fails closed when evidence is insufficient.” — AGENTS.md L17–19

The system is explicitly not a generic theological chatbot and does not perform open-web answer-time browsing, generic LLM query rewriting, or generated study packets (AGENTS.md L48–56). Orthodox Ethos is the first tenant in Phase 1, but the application is tenant-aware from day 1 (AGENTS.md L35; ADR-0003).

The repository is an implementation contract pack — it ships canonical contracts, ADRs, schemas, an OpenAPI file, task cards, and tests-as-skeletons. T-001 will scaffold the FastAPI/Next.js codebase (README.md L1–16; docs/DOCS_INDEX.md L18–105).

3.3 Invariants — preserved by every recommendation in this report

  1. Closed-corpus — A5 composes only from EvidencePacket; no training-data, open-web, or unapproved evidence (ADR-0001; AGENTS.md L60–64).
  2. Tenant isolation — every domain row carries tenant_id; Qdrant filters always include tenant_id AND approved=true; VectorFilter.tenant_id is a required dataclass field (ADR-0003; ADR-0013; vector-store-interface.md L111–119).
  3. Citation verification — deterministic A6 with ≥70% quote overlap, tenant-tunable only via safe config (quote-overlap-algorithm.md; AGENTS.md L128–129).
  4. Provider abstraction — LLMProvider, VectorStore, Reranker, Parser Protocols; no SDK imports outside adapters/ (ADR-0004; ADR-0010; code-gen-guide.md L221–234).
  5. Safety-suite gating — 20-query + paraphrase fuzz must pass for route certification (ADR-0004; phase1-implementation-contract.md L138).
  6. No generic LLM query rewriting — RetrievalPlan.semanticQuery = reframedQuery ?? rawQuery (ADR-0007; AGENTS.md L91–99).
  7. No draft-answer streaming before A6 — token events do not exist in Phase 1 (provider-interface.md L116–126).
  8. Run-trace persistence unconditional — every served request, including hard-safety bypass (phase1-implementation-contract.md L53).
  9. Prompt-injection defense — external content untrusted (CLAUDE.md §4).
  10. No secret exposure — secrets only in .env / Railway secret manager (CLAUDE.md §2).

3.5 Exit criteria for Phase 1 → Phase 2 (cited from phase1-implementation-contract.md L126–139)

  1. Safety suite stability: 14 consecutive calendar days passing in CI.
  2. ≥ 50 distinct internal queries served end-to-end.
  3. RED rate ≤ 30% (7-day rolling, hard-safety excluded).
  4. p95 query latency < 8 s over the last 7 days.
  5. Zero cross-tenant evidence admissions, cache leaks, log leaks, or admin-view leaks.
  6. ≥ 1 founder Phase-2 sign-off audit_entries row.
  7. ≥ 100 approved chunks across ≥ 5 distinct sources for Orthodox Ethos.
  8. Operational basics: RunTrace on every run; Stripe meter reported; retention worker has emitted ≥ 1 successful event.
  9. Safety configs are real (non-stub) and Greek-reviewed.
